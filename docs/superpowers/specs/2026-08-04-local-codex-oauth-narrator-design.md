# 로컬 Codex OAuth 서술기 설계

## 목표

Proofread 사용자가 자신의 PC에서 Codex에 직접 로그인한 뒤, 완료된 분석의 규칙 기반
finding을 바탕으로 짧은 한국어 개선 피드백을 생성한다. 점수와 finding을 생성하는
결정론적 평가기는 변경하지 않는다.

## 범위와 제약

- 기능은 로컬 실행 전용이다. 공용 배포 환경에서 사용자 계정을 대리 인증하거나 OAuth
  토큰을 보관하지 않는다.
- OAuth 자격 증명은 Codex CLI가 관리한다. Proofread API, PostgreSQL, Redis, Docker
  이미지와 애플리케이션 로그는 토큰·LLM 요청 본문을 저장하지 않는다.
- 현재 Compose 기반 분석 파이프라인은 변경하지 않는다. Docker 컨테이너는 Codex CLI나
  호스트의 인증 캐시에 접근하지 않는다.
- LLM에는 finding 코드, 우선순위, 이미 수집된 근거 목록만 보낸다. README 본문, GitHub
  토큰, 로컬 파일, 데이터베이스 정보는 보내지 않는다.

## 선택지와 결정

Docker 컨테이너에 호스트 Codex 인증 캐시를 마운트하면 구현은 단순하지만 자격 증명의
경계가 흐려진다. 서버에서 사용자의 OAuth를 처리하는 방식은 토큰 보관·세션·배포 보안을
추가로 요구한다. 따라서 브라우저와 같은 PC에서만 동작하는 별도 동반 프로세스를
선택한다.

## 구성 요소

### Codex 동반 프로세스

`proofread-codex-companion` 명령은 `127.0.0.1`에만 바인딩한 작은 HTTP 서비스다.
Codex CLI의 설치·로그인 상태를 확인하고, 기기 인증을 시작하며, 완료된 분석 리포트를
입력으로 서술을 생성한다. Compose와 별도로 사용자가 호스트에서 실행한다.

동반 프로세스는 다음 엔드포인트를 제공한다.

| 메서드 | 경로 | 역할 |
| --- | --- | --- |
| `GET` | `/v1/codex/status` | CLI 설치·로그인 가능 여부를 반환한다. |
| `POST` | `/v1/codex/login` | `codex login --device-auth`를 시작하고 사용자에게 필요한 인증 URL·코드를 반환한다. |
| `POST` | `/v1/codex/narratives` | 완료 리포트의 finding만 받아 검증된 서술 목록을 반환한다. |

동반 프로세스는 `Origin: http://localhost:8000`과 `Origin: http://127.0.0.1:8000`만
허용한다. 다른 Origin과 localhost 이외의 bind 주소는 거부한다.

### Codex 실행 어댑터

새 LLM 어댑터는 기존 `LlmClient` 프로토콜을 구현한다. `codex exec`는 프로젝트 파일이
없는 임시 작업 디렉터리에서 `read-only` sandbox로 실행한다. 출력은 JSON 스키마로
제한하며, 응답의 `finding_code`가 요청한 코드인지와 문안이 비어 있지 않은지를 기존
`narrate` 함수가 다시 검증한다.

Codex CLI가 없거나 로그인되지 않았거나 실행에 실패하면, 동반 프로세스는 명시적인
사용자 조치 오류를 반환한다. 규칙 기반 분석 결과는 이 오류의 영향을 받지 않는다.

### 브라우저 UI

분석이 `completed` 상태가 되면 UI는 AI 피드백 영역을 표시한다.

1. UI는 동반 프로세스 상태를 조회한다.
2. 미로그인 상태에서는 `Codex로 로그인` 버튼을 제공하고, 받은 기기 인증 안내를
   화면에 표시한다.
3. 로그인 상태에서는 `AI 피드백 생성` 버튼을 제공한다.
4. 버튼은 현재 화면의 완료 리포트를 동반 프로세스에 전달한다. 응답 문안은 기존
   finding 아래에만 표시한다.

동반 프로세스가 실행되지 않은 경우 UI는 로컬 AI 기능이 선택 사항임을 설명하고,
분석 리포트는 기존처럼 완전하게 표시한다.

## 데이터 흐름

`Compose API/worker → 완료 리포트 → 브라우저 UI → localhost 동반 프로세스 → Codex CLI`

응답은 같은 경로를 역방향으로 돌아와 브라우저에만 렌더링된다. AI 문안은 분석 레코드에
저장하지 않으므로, 새로고침 후에는 사용자가 필요하면 다시 생성한다.

## 오류 처리

- CLI 미설치: 설치·실행 명령을 안내한다.
- 미로그인: 기기 인증 시작을 안내한다.
- 인증 취소·시간 초과: 상태를 미로그인으로 돌리고 재시도를 안내한다.
- Codex 응답 실패·형식 오류: AI 문안만 비우고 기존 리포트를 유지한다.
- 동반 프로세스 연결 실패: UI에 로컬 전용 기능의 실행 방법을 표시한다.

## 테스트와 검증

- Codex 명령 실행기를 가짜 프로세스로 대체해 상태, 기기 인증, 성공·실패 응답을 단위
  테스트한다.
- 서술 요청이 finding 외의 필드를 Codex 입력으로 만들지 않는지 검증한다.
- 허용 Origin과 비허용 Origin의 CORS·bind 제약을 API 테스트로 검증한다.
- 브라우저 테스트는 동반 프로세스 상태에 따라 로그인·생성·폴백 UI가 바뀌는지 검증한다.
- 전체 pytest, Ruff, Compose 설정 검증을 수행한다.
